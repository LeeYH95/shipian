# 发布与恢复

仓库创建或可见性变更需要明确目标及授权。普通“看看项目”不构成发布授权；“上传到指定公开 GitHub 仓库”足以授权该范围的提交与上传，不重复索取同一许可。

上传前核对账号与远程。原项目目录含本地数据、受限制旧品牌素材或不宜公开的历史时，在独立目录创建可构建的发布副本，保留来源与许可，不改写或清空原目录。

提交文件使用白名单。排除真实用户笔记、截图、凭据、个人配置、运行日志、构建缓存和巨型临时文件。代码中的示例密钥也可能误触规则，审阅证据再决定，不为消除报警而删除有效测试。

优先复用安全的认证会话。用户自行完成登录和设备授权，Agent 只接收成功状态。不要将 Token 放入 remote URL、源码、脚本参数、清单或日志。

先校验本地产物，再提交推送；创建 Release 时清楚标注稳定版/预发行版，上传经过验证的安装包与校验和。已有仓库、标签和 Release 先读取，不重复创建，也不强推覆盖。

需要帮助认证时提供可操作入口，同时继续所有不依赖认证的工作。上传中断后读取远程状态，基于已成功部分恢复，不盲目重建。最终分别报告源码发布、素材发布、安装包发布的真实结果。
